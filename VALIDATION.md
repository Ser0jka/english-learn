# Отчёт о проверке Lexi

## Реализовано

UX/UI-аудит, конкретные проблемы и исправления: [UX_AUDIT.md](UX_AUDIT.md). Палитра и интерактивные состояния централизованы в `src/design-system.css`; добавлены онбординг, предварительная проверка импорта, доступные вкладки и диалоги, действия для пустых очередей, мобильная карточка значения и явные состояния помощника.

- Связное приложение с обзором, словарём, карточками, выражениями, чтением, настройками интересов и контекстной справкой.
- Добавление, поиск, изменение статуса, удаление слов; импорт TXT/CSV/JSON без дубликатов.
- Карточки с несколькими верными ответами, расписанием повторений и сохранением каждой попытки. Слова после ошибки возвращаются в повторение по наступлении срока.
- Выражения с употреблением, нюансами, историей, примерами и источниками; удаление выражения из словаря сбрасывает его отметку в списке выражений.
- Полная резервная копия коллекции, расписания, истории ответов, интересов, выбранных выражений и дополнительных текстов. Замена коллекции при восстановлении требует явной отметки в интерфейсе.
- Защита от повреждённых данных и некорректного импорта; видимое сообщение при невозможности сохранить данные; сохранение исходного повреждённого содержимого для восстановления.
- Проверка реального содержимого загружаемых изображений и уменьшение их размера.
- Безопасные серверные маршруты для подключаемого помощника, материалов и изображений, раздельная доступность текстовой и графической интеграций, ошибки сети и тайм-ауты.
- Мобильная навигация с управлением фокусом и Escape. Прямые hash-маршруты и история браузера.

| axe в составе Playwright                                    | 0 обнаруженных нарушений выбранных правил WCAG A/AA в проверенных экранах и состояниях |
| `npm audit --omit=dev --audit-level=high`                   | Уязвимостей в production-зависимостях не найдено                                       |

Итоговые JSON-отчёты Playwright находятся в игнорируемых Git каталогах `test-results/development/results.json` и `test-results/production/results.json`. В обоих: `expected=40`, `unexpected=0`, `skipped=0`, `flaky=0`. Режимы используют отдельные серверы, порты и каталоги результатов.

Браузерные проверки включают полную сессию карточек, верные и неверные ответы, CSV-файл, экспорт и восстановление всего прогресса после перезагрузки, удаление выражения, повреждённое хранилище, переполнение памяти браузера, контекст справки, мобильную клавиатуру, ошибочные HTTP-запросы и сломанный файл изображения. Добавлены 15 UX-проверок: пять экранов на четырёх ширинах (320, 390, 768, 1440 px), axe, отсутствие переполнения, онбординг, предварительный импорт, автоперевод, пустые состояния, управление фокусом, мобильное чтение, подключение помощника и повтор запроса после ошибки. Генерация проверена с контролируемыми тестовыми ответами, а не с реальным платным провайдером.

Workflow `.github/workflows/ci.yml` подготовлен для повторения проверок в GitHub Actions. Удалённый workflow в рамках этой задачи не запускался.

## Оставшиеся ограничения

- Без API-ключа доступны встроенные 24 слова, 12 выражений и 3 учебных текста, свой словарь, свои изображения и справка по материалам. Свободный диалог и генерация дополнительных материалов требуют ключа, прав у провайдера и разрешённого HTTPS-доступа к нему. Реальный провайдер не проверен: ключ не предоставлен.
- Подборки и частотность ограничены учебными данными; приложение не обещает исчерпывающий список всех идиом или подтверждённую историю для любого выражения.
- Прогресс хранится в текущем браузере, автоматической синхронизации между устройствами и аккаунтов нет. Полная резервная копия переносится вручную. Диалоги помощника не входят в копию.
- Проверки интерфейса выполнены в Chromium. Safari/Firefox, реальные телефоны и физические экранные дикторы не проверялись; автоматический axe не заменяет полную сертификацию WCAG.
- Произношение зависит от Web Speech API и голосов браузера/ОС; фактическое звучание голоса автоматическими тестами не подтверждалось.
- Перед открытым многопользовательским размещением платной интеграции нужны аутентификация и устойчивые ограничения запросов на уровне развёртывания. Текущий сценарий — личное приложение.

## Запуск

Node.js 24, из каталога репозитория:

```sh
npm ci
npm run dev
```

Порт по умолчанию — `5173`. Production:

```sh
npm run build
npm start
```

Настройка необязательного помощника описана в [README.md](README.md) и `.env.example`. Секреты должны оставаться в `.env.local` или защищённых переменных сервера.
