# Развёртывание на VPS

`install-server.sh` предназначен для Debian/Ubuntu с systemd, процессором x64/arm64 и публичным IPv4. Нужны root и входящие порты 22 (или ваш SSH-порт), 80, 443. Не запускайте установщик на другом дистрибутиве. Проверка на реальном VPS пока не выполнена: из облачной среды SSH-соединение прерывается до аутентификации.

Приватный пакет содержит собранное приложение, `app.env` с серверным ключом Groq, случайный пароль сайта и `ACCESS.txt`. Не публикуйте этот пакет или его содержимое в GitHub. Пароля SSH в пакете нет. Обычный клон репозитория не содержит секретов и готового приватного пакета.

На Mac распакуйте пакет и откройте `Deploy-to-server.command`. Подтвердите отпечаток SSH-сервера после сверки с панелью провайдера и введите пароль root. Альтернатива из Terminal:

```bash
cd /путь/к/распакованному/lexi-server-deploy
bash Deploy-to-server.command
# Если SSH работает на другом порту:
LEXI_SSH_PORT=2222 bash Deploy-to-server.command
```

Установщик ставит Node 24.19.0 с проверкой SHA-256, production-зависимости через lockfile, Nginx и systemd-службу `lexi`. Приложение работает от отдельного пользователя, слушает только loopback; ключ находится в `/etc/lexi/app.env`, доступном root. Релизы хранятся в `/opt/lexi/releases`, текущий — `/opt/lexi/current`. Чужие сервисы на портах 80/443 не останавливаются. Установщик предназначен для личного приложения, не для общего хостинга.

Для IP запрашивается сертификат Let's Encrypt с профилем `shortlived` через закреплённую версию acme.sh. HTTP должен быть доступен извне для проверки ACME. Таймер `lexi-certificate.timer` проверяет продление дважды в сутки; сертификат обновляется через 3 дня. Если выпуск не удался, установщик завершится с ошибкой и восстановит предыдущие конфигурацию и релиз. Резервные копии и диагностика остаются в закрытой папке `/var/lib/lexi-backup-*`. Доступность выпуска сертификата для конкретного IP проверяется только во время установки; самоподписанный сертификат не подставляется.

После успешной установки откройте HTTPS-адрес из `ACCESS.txt`, введите логин и пароль сайта оттуда. HTTP перенаправляется на HTTPS; Basic Auth защищает сайт и платные обращения к Groq. Ключ не передаётся браузеру. Установка проверяет health, доступность модели и реальную генерацию слов, затем HTTPS с проверкой сертификата. Это проверки установщика, а не отчёт о выполненном развёртывании.

```bash
systemctl status lexi nginx lexi-certificate.timer
journalctl -u lexi -n 100 --no-pager
nginx -t
systemctl restart lexi
```

При ошибке SSH уточните порт и проверьте доступ через Terminal или консоль провайдера. При ошибке ACME проверьте входящий порт 80 в firewall провайдера и журнал `acme.log` в каталоге диагностики. Установщик открывает 80/443 только в уже включённом UFW; правила провайдера он не меняет. При ошибке Groq исправьте `/etc/lexi/app.env` и перезапустите `lexi`. Не публикуйте файлы окружения или диагностические ответы модели.

Обновление: подготовьте новый приватный пакет с новым `RELEASE` и запустите тот же launcher. Предыдущий релиз сохраняется. Прогресс остаётся в браузере, синхронизации между телефоном и компьютером нет. Перед сменой адреса сайта экспортируйте прогресс: браузер хранит данные отдельно для каждого origin.
